# Decisions: S-001 manifests and validators

Each decision records what was chosen, why, and what would change it. Status is Proposed until it has been reviewed; then Agreed.

| ID | Decision | Why | Would change if | Status |
|---|---|---|---|---|
| D-S1-01 | Language is Python | Python validator tooling aligns with the Python components of `taffee-context` (D-007). Context is mixed TypeScript and Python, so this is a preference, not toolchain parity. The schemas and index formats stay language-neutral. | The Context code is ported away from Python | Proposed |
| D-S1-02 | Schemas are JSON Schema draft 2020-12, one per kind | Standard, readable by any tool, and the same format the tool inputs use | A validator library cannot support the draft | Proposed |
| D-S1-03 | Two digests. `manifest_digest` identifies the declaration. `code_digest` identifies the implementation, for `library` sources. An `external` source is a pinned reference (repository, commit, `tree_sha256`), and its label is capped at Declared until the code moves into `library/`. | A manifest-only digest must not imply that the running code was reviewed. A pinned external reference gives code integrity without copying the code. (from review) | The source moves into `library/` (T-001), which adds `code_digest` and lifts the cap | Proposed |
| D-S1-09 | The index records `inputs_digest` over `catalog/`, `schemas/`, `policy/` and `library/` (excluding `index/`), not a commit SHA. The claim is narrow: the inputs digest identifies the recomputed inputs. It is not commit provenance. S-005 attaches the committed index's Git SHA externally. | A committed file cannot contain the SHA of the commit that includes it.  | A consumer needs commit provenance inside the index; then S-005 or a later feature adds it, not a self-reference | Proposed |
| D-S1-10 | Golden digests are generated inside the test image on the Linux test host and committed. A fresh clone on the Linux test host, in a different directory, must reproduce them. This is same-host clean-clone reproducibility, not cross-host proof. | The Mac is not a test host (project rule). Cross-OS proof needs a host the owner permits. (the reviewer round 1 point 6; round 2 agreed.) | The owner permits a Mac run or a third host is added | Proposed |
| D-S1-04 | Digest algorithm `sha256-tree-v1`: sorted relative paths; text files hashed over their LF-normalised content (CRLF becomes LF), so the digest identifies normalised content, not raw bytes; text is detected as no NUL byte in the first 8000 bytes, and other files are hashed unchanged; symlinks and non-regular files are refused, never followed; per-file SHA-256, then SHA-256 over the listing | Simple to reimplement in another language; does not depend on file modes, timestamps or filesystem order; refusing links prevents a digest that reads outside the tree | A collision, a portability problem, or a need to hash raw bytes is found | Proposed |
| D-S1-05 | One canonical JSON form for everything: UTF-8, sorted keys, two-space indentation, LF line endings, final newline. The index file, the manifests it embeds, and every JSON digest input use this form. `manifest_digest` is the SHA-256 of the canonical JSON of the parsed manifest, so YAML formatting and comments do not change it. The index carries its own digest over this form with `index_digest` removed. | Byte-stable, so two runs can be compared, and the digest input is unambiguous | A consumer needs a different format | Proposed |
| D-S1-06 | Labels are computed by a versioned policy file (`policy/labels.yaml`); manifests cannot set a label | A label must be re-derivable from evidence. A manifest that sets its own label proves nothing. | n/a | Proposed |
| D-S1-07 | Validation failures stop the index build; the index is not written | A partial index would look complete to a consumer | A need for partial publication, decided explicitly | Proposed |
| D-S1-08 | Tests run in the Python 3.12 container image on the Linux test host, not on the editing machine | Project rule: no tests on the editing machine; the container pins the version | The Linux test host cannot run containers | Proposed |
| D-S1-11 | S-001 labels every capability Declared and awards nothing above it. Validated for tools is defined in T-001, with the entry format and export check. | Validated needs an entry format that S-001 does not define, so awarding it would overstate the evidence. (review point 1) | T-001 defines the entry format and export check | Proposed |
| D-S1-12 | The `library/` folder is optional. An absent `library/` contributes nothing to `inputs_digest`, the same as an empty folder. | A clean Git clone cannot hold an empty folder, so an external-only catalog would otherwise fail to build. (review point 2) | A library folder is required by a later feature | Proposed |
